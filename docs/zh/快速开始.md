# 快速开始

> 本文假设你已经用上游 [arch-xiaomi-pad8](https://github.com/KoryoSony/arch-xiaomi-pad8) 的 `v0.1.0-alpha` 资产把 Arch Linux 装到了平板（`boot.img`、`init_boot.img`、`userdata.part1..6.img` 都刷过一遍）。本仓库只替换**内核**，其余资产仍从上游 release 取。

## 1. 确认底包与解锁状态

```bash
adb shell getprop ro.build.display.id     # 期望 OS4.0.5.0.XPZCNXM
adb shell getprop ro.boot.vbmeta.device_state   # unlocked
```

底包不是 4.0.5 的机器，`/vendor` 里的模块来自另一套供应商树，模块 CRC 与本内核不匹配 —— 请先按上游文档回退到底包。

## 2. 刷内核

从 [Releases](../../releases) 下载 `boot.img`，然后：

```bash
adb reboot bootloader
fastboot flash boot boot.img
fastboot reboot
```

- 刷写目标是活动槽的 `boot`（本机为 `boot_b`），`fastboot` 会自动选当前槽。
- 不要动 `vbmeta`，不要动另一个槽，保底可回退。
- 校验哈希：

```bash
sha256sum boot.img
# 6cef2b6e6f50b37c5b18eeab500e717a8e79dc830743b1f058f4563ea98e9b67
```

## 3. 首次开机后跑装机脚本

```bash
git clone https://github.com/wrightgilbert/pad8-arch-linux-flatpak
bash pad8-arch-linux-flatpak/scripts/post-install.sh
```

脚本做三件事：

1. `chmod 755 /usr/bin/bwrap` —— 上游镜像里的 bubblewrap 带 setuid 位，而我们提供了 `USER_NS`，setuid 模式会被 bubblewrap 自己拒绝；
2. `flatpak remote-add --user flathub …`；
3. 跑 `scripts/verify.sh` 自检。

## 4. 验证

```bash
flatpak install --user flathub org.gnome.Calculator
flatpak run org.gnome.Calculator
```

也可以只跑自检：

```bash
bash pad8-arch-linux-flatpak/scripts/verify.sh
```

期望输出（节选）：

```

  [OK]   CONFIG_SYSVIPC=y
  [OK]   CONFIG_IPC_NS=y
```

## 出问题怎么办

| 症状 | 原因 | 处理 |
|---|---|---|
| 卡在开机 Logo，USB 也不出 | 内核起来了但一个模块都载不进来（`0001`/`0002` 未生效，或底包不对） | 刷回上游 `boot.img`，确认底包为 4.0.5 |
| `bwrap: setuid use of bubblewrap is not supported` | `/usr/bin/bwrap` 还带 setuid | `sudo chmod 755 /usr/bin/bwrap` |
| `bwrap: Can't mount proc on /proc: Operation not permitted` | 内核缺 `0003` | 确认 `uname -r` 是否为 `6.6.118-4k-arch+` |
| `flatpak run` 报 `ldconfig failed` | 沙箱起不来导致后续命令全挂 | 先解决上一条 |
| 装 GNOME 运行时很慢 | Flathub 体积（约 2.5 GB） | 正常现象 |

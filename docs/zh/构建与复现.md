# 自己编译（aarch64 主机）

产物 `boot.img`（`sha256 6cef2b6e…9b67`）就是在平板本机上编出来的：8 核约 10 分钟，峰值内存约 6 GB。树莓派 5 之类的 aarch64 机器也能编，只是慢 2-3 倍。

## 0. 前置

- 任意 aarch64 Linux（本项目在 Arch Linux ARM / 平板原生环境上验证）。
- 磁盘：内核树 + 构建目录约 20-25 GB。
- 依赖（Arch）：`base-devel bc bison flex libelf cpio rsync git curl zstd lz4 python`。

## 1. 拿 LLVM 18.1.8

上游移植的 `config.sh` 里钉的是 AOSP 的 `clang-r510928`，但**该工具链已从 AOSP 仓库移除**（`refs/heads/main`、`refs/tags/android-15.0.0_r1`、`refs/heads/android15-release` 三处均为 HTTP 404）。厂商内核的 `CONFIG_CC_VERSION_TEXT` 是裸的 `clang version 18.1.8`，所以用 LLVM 官方同版本即可：

```bash
mkdir -p ~/llvm18 && cd ~/llvm18
curl -LO https://github.com/llvm/llvm-project/releases/download/llvmorg-18.1.8/clang%2Bllvm-18.1.8-aarch64-linux-gnu.tar.xz
tar -xf clang+llvm-18.1.8-aarch64-linux-gnu.tar.xz --strip-components=1
clang --version | head -1     # clang version 18.1.8
```

x86_64 主机换成 `clang+llvm-18.1.8-x86_64-linux-gnu-ubuntu-18.04.tar.xz`，见文末“已知坑”。

## 2. 两个已知编译坑

**a) `ld.lld` 依赖 `libxml2.so.2`.** Arch 的 libxml2 只提供 `libxml2.so.16`，链接器直接报找不到：

```
ld.lld: error while loading shared libraries: libxml2.so.2
```

软链一下即可（会打印 `no version information available` 警告，不影响使用）：

```bash
sudo ln -sf /usr/lib/libxml2.so /usr/lib/libxml2.so.2
```

**b) `resolve_btfids` 编不过.** BTF 的宿主工具在 Arch 的 asm 头下失败：

```
/usr/include/asm/sigcontext.h:81:2: error: unknown type name '__u128'
```

`scripts/build-kernel.sh` 会往配置片段里写 `# CONFIG_DEBUG_INFO_BTF is not set` 绕开。BTF 只影响调试信息，不影响启动、模块或 KMI。

## 3. 编译

```bash
git clone https://github.com/KoryoSony/arch-xiaomi-pad8
git clone https://github.com/wrightgilbert/pad8-arch-linux-flatpak

cd arch-xiaomi-pad8
PORT=$PWD TC=$HOME/llvm18 PATCHES=../pad8-arch-linux-flatpak/patches \
    bash ../pad8-arch-linux-flatpak/scripts/build-kernel.sh
```

脚本做的事：

1. clone 内核 `android15-6.6-2026-01_r37`（= 澎湃 OS 4.0.5 对应的 GKI tag）；
2. 依次打 `patches/0001..0003`（幂等，已打过会跳过）；
3. 往 `kernel/yupei-linux.fragment` 追加 `CONFIG_SYSVIPC=y / CONFIG_IPC_NS=y / CONFIG_PID_NS=y / CONFIG_USER_NS=y` 与 BTF 关闭项；
4. 调上游 `kernel/build-kernel.sh`（`LLVM=1`、`gki_defconfig`、`merge_config`、`olddefconfig` 后逐项校验 fragment）；
5. 产物落在 `out/`：`Image`、`Module.symvers`、`.config`、`kernel.release`。

期望 `out/kernel.release` 为 `6.6.118-4k-arch+`，`Image` 约 30 MB。

## 4. 换内核进 boot.img

```bash
python ../pad8-arch-linux-flatpak/scripts/mkboot.py \
    --base boot.img --kernel out/Image --out boot-flatpak.img
```

`--base` 用上游 release 的 `boot.img`（v4、`ramdisk_size=0`、无 AVB 签名）。脚本会校验头部字段、回写 `kernel_size`、按 4096 补齐，并检查 cmdline 未变。

## 5. 刷机

```bash
adb reboot bootloader
fastboot flash boot boot-flatpak.img
fastboot reboot
```

## 已知坑（x86_64 主机 / CI）

- **AOSP `clang-r510928` 已经下载不到**：`+archive/` 形式在 CI 里返回 HTTP 400，`curl` 之后 `gzip: stdin: unexpected end of file`。
- 用 LLVM 官方 x86_64 18.1.8 tarball 时需要补 ncurses 兼容软链（该 tarball 构建于 Ubuntu 18.04，依赖 `libtinfo.so.5`）：

```bash
sudo ln -sf /lib/x86_64-linux-gnu/libtinfo.so.6 /lib/x86_64-linux-gnu/libtinfo.so.5
sudo ln -sf /lib/x86_64-linux-gnu/libncurses.so.6 /lib/x86_64-linux-gnu/libncurses.so.5
sudo ln -sf /lib/x86_64-linux-gnu/libncursesw.so.6 /lib/x86_64-linux-gnu/libncursesw.so.5
sudo ldconfig
```

- 本项目**没有随附 GitHub Actions workflow**：x86_64 容器里这条链路的最后一步没跑通，aarch64 上则已完整验证。想用 CI 的话，把上面三处软链加进作业的 `run` 步骤即可。
